- **决策**：第一款游戏做《当铺纸牌》（卡牌构筑 Roguelite + 轻经营）。

## 2026-11-24 — 推送路径走 Muse GitHub 连接器，不走 shell gh
- **决策**：AGY 在 shell 本地写代码，协调员经 Muse GitHub 连接器（MCP）`push_files` 快照推送到 `feature/m0-scaffold` 分支，再开 PR、合 main。
- **理由**：shell 里 `gh` 未登录、无 token；连接器已验证连通（账号 zhuuchaofan，仓库可读）；快照推送满足纯文本脚手架的推送需求。
- **影响**：推送不经过本地 git 历史（无本地提交记录）；删除、二进制文件需另走 `delete_file` / `create_or_update_file` 单独处理；后续每次推送都要按 snapshot-push 规范做同步记录。

## 2026-11-24 — AGY 调用须加 --dangerously-skip-permissions
- **决策**：AGY 以 print 模式运行时附加 `--dangerously-skip-permissions`。
- **理由**：实测：不加该参数时 print 模式无法提示授权，`read_file` 权限被自动拒绝，任务 9 秒即失败。加参数后任务正常进行。
- **风险与约束**：该参数会放行 AGY 的全部工具调用；缓解措施是任务书明确红线（不提交、不推送、不碰 GitHub、不写凭据、不联网收费服务）+ 协调员事后审查 AGY 的实际操作记录。长期应改为在 settings.json 里配最小权限 allow-rule（待 M0 后评估）。
- **影响**：M0 之后每次 AGY 调用都须带该参数，直到权限配置方案落地。

## 2026-11-24 — Vite base 用 './' 相对路径，不写死子路径
- **决策**：`vite.config.ts` 加 `base: './'`；禁止写死 `'/game-studio/'`。
- **理由**：试玩页在 Pages 子路径下全黑，查实是默认 `base: '/'` 使 `dist/index.html` 引用
  `/assets/...` 绝对路径，在 `/game-studio/` 下 404；相对路径使构建产物在任意子路径下都能加载，
  换托管路径不用改代码。
- **影响**：`dist` 引用全部相对化；本地 `vite preview` 与根路径部署不受影响。

## 2026-11-24 — 回归测试必须把 dist 挂在子路径下跑
- **决策**：新增 `tests/e2e/subpath.spec.ts`：测试内自启静态服务器把 `dist` 挂在
  `/game-studio/` 下，断言画布渲染出来且无失败请求；该测试必须能在旧构建上失败、新构建上通过。
- **理由**：原有 smoke 测试只在根路径跑，查不出子路径 404；本次 bug 就是这样漏网的。
- **影响**：CI 每次都跑该测试；以后改 base 或部署路径，测试先报警。

## 2026-11-24 — 机制卡 1 收当口碑规则改为成交结算且自洽
- **决策**：口碑只在成交时结算（低价成交 −1、平价 +0、高价 +1），任意档位被拒一律 +0；报价三档（50%/100%/150%）与接受率（30%/80%/100%）保持不变。
- **理由**：原草稿数值行写“−1（低价被拒时不扣，低价接受时 +0）”自相矛盾，导致低价没有口碑代价。
- **影响**：低价形成“高利润 + 掉口碑”的真实取舍，与高价（亏钱 + 涨口碑）、平价（中庸）构成三难选择，原型试玩重点验证玩家是否真的纠结。

## 2026-11-24 — 引入 mulberry32 种子随机数并支持 URL 参数 `?seed=`
- **决策**：新增 `src/utils/rng.ts` 实现 `mulberry32` 确定性伪随机数生成器；默认从 URL 查询参数 `?seed=` 读取种子，缺省时回退到 `Date.now()`。
- **理由**：收当接受率（低价 30% / 平价 80%）包含概率分支，固定种子使 Playwright E2E 能稳定覆盖接受与拒绝两条路径，避免测试抖动。
- **影响**：正常玩家不传 `?seed=` 时每次体验仍随机；测试与复现 bug 时可通过 `?seed=<n>` 精确重现随机序列。

## 2026-11-24 — “当票”弃手牌最左 1 张（不含自身）且独手不可打出

- **影响**：场景不写死技能名或伤害值，新心魔只需在 `src/data/demons.json` 中配置 `actions` 与 `skill` 即可自动提示。

## 2026-11-24 — P2 胜利奖励规则（占位数值）
- **决策**：打赢心魔在 `ResultScene` 结算得钱 `winRewardMoney`（`balance.json` 占位 20）+ 从 20 张牌表中用种子 RNG（`?seed=`）随机抽 1 张不在当前牌组中的新牌 + 赎当券 ×1（占位仅展示，P3 使用）；若 20 张已全在牌组中则改为额外得钱 `+winRewardMoney`（共 +40）。
- **理由**：满足 GDD“打赢得新牌 + 钱 + 赎当券”循环，同时保证种子随机可被 E2E 精确断言，且不提前引入 P3 的跨天存档与持久化。
- **影响**：所有奖励数值由 `balance.json` 与 `cards.json` 驱动；P3 串联一天流程时可直接复用 `resolveWinReward`。

## 2026-11-24 — P2 蒙特卡洛贪心策略与首次 1000 局胜率结论
- **决策**：在 `src/game/montecarlo.ts` 实现确定性贪心策略（仅当本回合伤害致命时优先出护盾牌；其余回合按“伤害/人情比”从高到低出伤害牌，再按费用从低到高出非护盾功能牌，非致命时不盲目打出倒转撤销自身伤害），对 A/B 各跑 1000 局（种子 1～1000）。
- **理由**：量化验证 GDD 第 9 节第 6 项（A 20 血、B 18 血能否在 3 回合内打死），为后续数值调优建立基线，本次暂不硬编码高胜率阈值也不擅自改 GDD 数值。
- **影响**：首次模拟结论——心魔 A（20 血）胜率 **91.3%**、平均结束回合 **2.99**、胜局平均剩余生命 **24.05**（超时负 87 局、血量归零 0 局）；心魔 B（18 血）胜率 **97.3%**、平均结束回合 **2.76**、胜局平均剩余生命 **26.50**（超时负 27 局、血量归零 0 局）。两者均可 3 回合击杀，但玩家 30 血下几乎无生存压力（所有败局均为 3 回合超时），留待制作人评审后决定是否在 P3 调整 JSON 数值。

## 2026-11-24 — 牌组为空仍可进入夜里牌局并提示“没有牌可打”
- **决策**：白天收当全被拒导致 `state.deck` 为空时，结算屏“进入夜里牌局”按钮仍可点击；进入 `CardBattleScene` 后若牌组为空（且未传 `?deck=test`），直接展示“没有牌可打”与“返回标题”按钮，不静默替换成测试牌组。
- **理由**：按任务书要求如实反馈白天未收牌的结果，避免静默塞入 10 张测试牌误导玩家或掩盖真实流程缺陷。
- **影响**：玩家路径与测试路径（`?deck=test`）边界清晰；P3 设计完整一天流程时可据此决定是否赠送保底牌或提示重试白天。

## 2026-11-24 — 铁皮青蛙条件分支澄清为“敌方此前回合已行动”
- **决策**：19 号牌“铁皮青蛙”（`damage_conditional`，`value: 3, bonus: 3`）的触发条件由字面“敌方本回合已行动”澄清为“敌方此前回合已行动”——在 `BattleState` 中用持久标志 `demonHasActed`（初始 `false`，`endTurn` 心魔行动时置 `true` 且不再重置）取代原 `demonActedThisRound`，使铁皮青蛙在 R1 打 3 伤、R2/R3 打 6 伤；`src/data/cards.json` 效果声明不变，`docs/GAME_DESIGN.md` 为定稿文档暂不动，交由制作人定夺是否修订措辞。
- **理由**：本作牌局为玩家先手回合制（玩家仅能在 `play` 阶段出牌，心魔在 `endTurn` 的 `demonAct` 阶段才行动）；原 `demonActedThisRound` 进入下一回合即重置为 `false`，导致真实对局中玩家出牌时该标志恒为 `false`，铁皮青蛙永远只能打 3 伤、严格弱于 1 费 4 伤的“钢笔”，沦为违背 GDD 验证清单“无废牌”要求的废牌。
- **影响**：铁皮青蛙确立为“R1 较弱（3 伤）、R2/R3 发力（6 伤）”的后手爆发 1 费牌，与钢笔（恒定 4 伤）形成清晰取舍；`src/game/effects.ts`、`src/game/battle.ts`、`src/game/montecarlo.ts` 及单测同步使用 `demonHasActed` 并补充跨回合状态机集成用例。
