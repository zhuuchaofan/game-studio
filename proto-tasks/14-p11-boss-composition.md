## 子项 1：Boss 组合（headline）

- **一句话定义**：第 7 夜的 Boss 不再是固定 38 血的"收账的人"，而是「老债主 + 玩家本章收下且未赎回的每件旧物的执念」拼成的组合体。白天每收一件旧物，等于往 Boss 身上添了一块；每赎回一件，等于从 Boss 身上拆掉一块。
- **组件表（Q1 选项 A：血量 + 碎片；Q2 选项 A：全盘接受，按提案 §1.4，一字不差）**：

| 旧物（牌） | 组件名 | 效果 |
|---|---|---|
| 旧手表（倒转，2 费） | 倒转的执念 | Boss 血量 +2；R4 伤害 +2 |
| 婚戒（守诺，1 费盾 5） | 守诺的执念 | Boss 血量 +2；R1 开局盾 +5 |
| 旧书（旧书，1 费抽 2） | 旧账的执念 | Boss 血量 +2；R1/R2/R3 伤害各 +1 |
| 永久自行车（飞驰，2 费 6 伤） | 飞驰的执念 | Boss 血量 +2；R4 伤害 +3 |
| 二胡（余音，1 费 3 伤 +1 情） | 余音的执念 | Boss 血量 +2；R3 伤害 +2 |
| 邮票册（集邮，1 费抽 1 +1 情） | 集邮的执念 | Boss 血量 +2；封门打断阈值 +4（10→14） |

- **血量基数与上限（Q3 选项 A）**：基础血量 **32**（典型 3 块时 32 + 2×3 = 38，恰好等于现行值）；每块 +2；组合上限 **44**（32 + 12）；赊账进货 +6 直接叠加，但 Boss 血量绝对上限 **48**（满配 44 + 赊账 6 = 50 → 按 48 截断；**截断须在战前预告里写明"已到顶"，不得静默吞掉**）。
- **计数（提案 §1.3）**：第 7 夜开战瞬间，牌库里**去重后**的旧物牌种类数；同一件旧物买两次只算 1 块；仅 6 张旧物牌计入（倒转 / 守诺 / 旧书 / 飞驰 / 余音 / 集邮），胜利奖励的 17 张非旧物牌不算；第 7 天白天最后一次收当 / 赎当仍能改变构成。
- **0 块兜底（素体）**：牌库里一张旧物牌都没有时，Boss 回落为"素体"形态：基础血量 + 封门招式，无任何组件加成，开场横幅写明「柜子空了，债主只身前来」——不得出现无 Boss、无战或报错。
- **封门打断原样保留**：R2 蓄力 +4 盾、本回合累计 ≥10 原始伤害打断、返 +1 人情、R3 未打断 11 / 打断 3，一字不动；组合只在它身上做加法，不改它的规则。打断口径沿用现行（按原始伤害累计，含被盾吸收的部分）。
- **赎当单向削弱（含新娘事件，Q4 选项 A）**：赎回一件旧物 → 其卡牌离库 → 第 7 夜结算时该组件不存在；第 2 天新娘事件接受赎当 = 婚戒组件永久移除（本局不再出现），拒绝 = 婚戒组件保留。赎当不得反向增强 Boss。赎当结算本身一字不动。
- **可见性三处递进（Q10 选项 A，全部复用已有界面，不新增常驻 HUD 元素）**：
  1. 台历屏第 7 天格子下方常驻预览（从第 1 天起可见）：一行组件徽章（每块 12×12 像素小图标，复用旧物 32×32 像素画的缩略或首字，P9 徽章带已有实现范式），已收未赎的逐个亮起，未收 / 已赎的置灰；一行小字：「第 7 夜，债主带着 X 件旧物的执念上门（Boss 约 Y 血）」，X、Y 随收当 / 赎当实时变。每次成功赎当后，组件预览**立即减一块**。
  2. 第 7 天白天开张前「封门预告」（一次性弹窗 / 横幅）：列出 Boss 当前完整构成——血量（基础 32 + 组件 +2×n + 赊账 +6，注明上限 48）、每块组件的一行效果（如「婚戒的执念：开局盾 +5」）、封门打断阈值（10 或 14）。目的：让玩家在第 7 天最后一次收当 / 赎当决策时有完整信息。
  3. Boss 战开场横幅：按组件列出碎片名，如「手表的执念 · 婚戒的执念 · 自行车的执念」，配一句总述「柜子里的事，今夜一起上门了」；0 块时为「柜子空了，债主只身前来」。战报 / 结算页可附一行「执念清单」：本战生效的组件及其实际贡献。
- **实现落点（提案 §1.8，供实施参考）**：组件效果表进 JSON（`demons.json` 的 `boss_ch1` 段或 `chapters.json` 的 Boss 配置段，二选一，由实施轮次定；表结构：`itemId → { hpBonus, roundDeltas, shield, chargeThresholdDelta }`）；新增 `src/game/bossComposition.ts` 纯函数（输入第 7 夜开战时牌库 + 契约状态，输出 Boss 完整定义），便于单测与 sim 直接调用，不得在战斗引擎里为每件旧物写特判；`src/game/battle.ts` 只接"算好的 Boss"，不接"组件"，封门打断逻辑（`BOSS_CHARGE_INTERRUPTED`）一字不动；可见性改动在 `CalendarMapScene.ts`（组件徽章 + 血量预告）、`PawnshopScene.ts`（第 7 天封门预告）、`CardBattleScene.ts`（开场横幅碎片名）；`validate.ts` 校验组件表引用的旧物 / 牌全部存在；组合由牌库**实时算出**，不另存"组件清单"字段（唯一新增持久字段见子项 2 父亲事件）。
- **设计原则（提案 §1.2，约束一切数值）**：收当仍是净收益，不得变成惩罚；赎当是唯一的泄压阀，且必须可见；封门打断机制不动；全部数据驱动。
- **关键风险数字（提案 §1.5/§1.9，sim 必须验证）**：满配未打断四回合总伤 30 = 玩家满血 30，满配下打断从"可选项"变"必选项"；邮票册阈值 14 的打断可达性须单独验证，若低于护栏下限，触发备选（邮票册组件改为 R2 盾 +2，不动阈值——Q2 拍板记录已定此备选，不另定）。

## 验收标准

1. `npm run build` 退出码 0；`npx tsc --noEmit` 0 错误；`npx vitest run` 全过；`npm run test:e2e` 全过（只跑 localhost）；`npm run sim:check` 全过（含新增的组合 Boss 扫描模式与新护栏）。
2. 新增单测：组合结算（0/1/3/6 块、赊账叠加、上限截断、0 块兜底、重复购买去重）、赎当削弱（赎一件少一块，含新娘事件赎走婚戒）、条件文案分支（有 / 无对应旧物）、父亲事件触发条件（手表在库 / 已赎 / 未收三态）、D1 冷却（赎回后 N 天内不出现、冷却期过后可出现）、D2 优先未拥有（池子不足时放宽）。
3. 新增 E2E：台历组件徽章随收当 / 赎当实时变化；第 7 天封门预告数字与实际 Boss 一致；Boss 战开场横幅列出碎片名；新娘事件赎走婚戒后 Boss 少婚戒组件；父亲事件接受 / 拒绝两路；结局翻账本逐件点名与实际赎当记录一致；赎回后次日当客池无该旧物（D1 冷却）。
4. 浏览器实测截图（localhost）：台历组件预览、封门预告、Boss 开场碎片名、结局翻账本、父亲事件画面——画面、文字须亲眼核实，不能只看编译成功；320×180 像素对齐，无文字溢出、无遮挡。
5. 本地构建 + 单测 + E2E 全绿之前一个提交都不推；一次提交、一次推送、一个 PR；PR 描述写清组合 Boss 各档实测胜率与护栏对照、D1 的 N 取值与理由。
6. 不合并——合并等制作人确认；合完由负责人（Muse）截图验 live 页。
7. 回归：P6–P10 已有功能（收当三档、口碑、性格、随机赎当、新娘事件、落败恢复、教程、章节 / Boss / 台历、存档、音效）不得回退，现有 E2E 全套须过；随机赎当与新娘事件结算逻辑一字不动（组合只读牌库，不改赎当结算）；药费 20 不动，首夜基线 28.5% / 8.8% 不变。
